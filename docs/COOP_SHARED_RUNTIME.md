# 기존 게임 기반 2인 코옵

## 구현 범위

별도 고정 보드 전투를 제거하고 `index.html?coop=1`에서 기존 게임 엔진·렌더러를 실행한다. `coop-runtime.js`는 기존 이동, 공격, 특성, 승급, 아이템, 지형, 보스 함수를 호출하고 플레이어별 상태를 교체한다. `coop-session.js`는 전투 규칙 대신 실행 순서와 선택 시간을 담당한다.

- 몬스터 행동 → 선공 플레이어의 차례 → 다른 플레이어의 차례 → 몬스터 행동. 선공은 웨이브마다 P1과 P2가 번갈아 맡는다(v0.17.0).
- 각자 자기 차례에 1.8초의 선택 시간을 받는다. 수를 고르면 남은 시간을 기다리지 않고 바로 진행한다. 시간 안에 고르지 않으면 이동 없이 차례가 넘어간다. 이동할 수 있는 칸이 없는 플레이어는 건너뛴다.
- 공격·아이템·특성이 기존 규칙상 차례를 유지시키면 1인처럼 그 플레이어가 연쇄가 끝날 때까지 계속 움직인다. 이어지는 행동마다 새 선택 시간을 받는다. 두 플레이어 모두 차례를 마쳐야 몬스터가 움직인다.
- 뒤에 움직이는 플레이어는 앞 플레이어가 실제로 움직인 결과를 보고 고른다. 동시 선택 때 필요했던 재선택 규칙은 없앴다.
- DEV AUTO는 1인 AUTO처럼 0.28초 생각한 뒤 수를 낸다. `다음 단계`는 기다리지 않는다.
- v0.18.0부터 경험치·레벨·특성은 팀 공유다(`BALANCE.teamTraits`). 두 사람의 처치 XP가 막대 하나에 쌓이고, 레벨업시킨 플레이어가 그 자리에서 보상을 고르면 두 기물 모두에 적용된다. 한 레벨에 필요한 XP는 1인의 2배다(`BALANCE.xpScale`). 첫 팀 레벨에서는 두 폰이 함께 승급하고, 이후 `말 바꾸기`는 고른 사람의 기물만 바꾼다. 기물·리롤·체인·일시 강화는 플레이어별, 점수·적·아이템·지형은 공유한다.
- 2인 모드에서는 1인 특성 대신 2인 전용 특성만 나온다. 모두 동료가 있어야 작동한다.
  - 연결선: 직접 처치 시 나와 동료 사이 일직선 위의 일반 적을 타격한다.
  - 공명 파동: 직접 처치 시 동료 주변의 일반 적을 타격한다.
  - 협공 일격: 동료가 가까이 있을 때 직접 처치하면 내 주변의 일반 적을 타격한다.
  - 집결: 동료가 가까이 있으면 기본 사거리가 늘어난다.
  - 합류: 이동 대신 동료 옆 빈칸으로 바로 이동한다. 팀 공유 재사용 대기가 있다.
  - 핀: 두 플레이어가 가로·세로·대각선으로 나란히 서면 그 사이에 끼인 일반 적이 적 턴에 움직이지 못한다. 화면에는 두 기물 사이 노란 점선으로 표시한다.
  - 수호: 동료가 가까이 있을 때 적에게 잡히면 동료가 그 적을 되잡고 살아남는다. 팀 공유 재사용 대기가 있다.
  - 캐슬링: 이동 대신 동료 칸을 눌러 동료와 자리를 바꾼다. 팀 공유 재사용 대기가 있다.
  - 릴레이: 직접 처치 시 동료의 다음 이동 사거리가 늘어난다.
  - 레벨별 수치는 `traits.js`의 `COOP_DEFINITIONS`에 있다. 2인 특성에는 아직 숙련·조합이 없다.
  - 동료가 쓰러지면 그 자리에 점선 원 표식이 남는다. 연결선·공명 파동·협공 일격·핀·집결은 표식을 동료 위치로 보고 계속 작동한다. 수호·캐슬링·합류·릴레이는 살아 있는 동료가 있어야 작동한다.
  - AUTO는 캐슬링·합류가 동료를 어디로 옮기는지 판단하지 못하므로, 다른 안전한 수가 없을 때만 이 두 이동을 쓴다.
  - 측정 근거는 `docs/balance/coop-v0180-report.md`에 있다.
- 각자 카메라를 사용하며 행동 중에는 행동하는 동료를 따라간다. 동료는 흰색 기물·흰색 블룸과 P1/P2 이름표로 표시한다. 화면 밖 동료는 흰색 원형 테두리·블룸 안의 P1/P2 문자와 방향 삼각형으로 표시해 내구도 색을 쓰는 적과 구분한다.
- 자신의 행동이 소진되면 동료의 연속 행동을 선택 시간까지 계속 따라본다. 두 명 모두 생존해 있으면 자기 선택 중·적 턴·동료 턴 모두 `내 말 보기 / 동료 보기`를 사용할 수 있다. 다음 자신의 이동 선택 기회에는 자동으로 자기 말로 복귀하지만 그 후 다시 동료를 볼 수 있다. 동료를 보더라도 선택 입력은 자기 말의 합법적 이동에만 적용된다. DEV에서는 `조작 P1/P2`로 시점 전환 버튼의 대상을 고른다. 시점 선택은 로컬 상태라 다른 플레이어의 카메라에 영향을 주지 않는다.
- 한 명이 잡히면 다른 플레이어는 계속 플레이한다. 생존자가 레벨업하면 보상 패널에서 먼저 `동료 부활 / 내 보상 받기`를 고른다(v0.17.1). 부활을 고르면 그 레벨의 보상을 포기하고, 동료가 내 옆 빈칸에서 자기 기물을 유지한 채 돌아온다(레벨·특성은 팀 공유). 돌아온 동료는 준비 박자 2 동안 잡히지 않는다. 첫 승급(폰 → 새 기물)에서는 부활을 제시하지 않는다. 횟수 제한은 없지만, 부활한 뒤 30웨이브 동안은 다시 부활을 제시하지 않는다(v0.17.3, `BALANCE.reviveCooldown`). 대기 중에는 보상 안내에 남은 웨이브를 보여 준다. 부활하면 이전 사망 복기 기록은 지우고, 다시 죽으면 새로 기록한다.
- 먼저 죽은 플레이어에게 개인 사망 안내와 `사망 직전 10수 보기 / 동료 관전`을 제공한다. 관전 중에도 복기를 다시 열 수 있다. 둘 다 죽으면 점수·웨이브·처치 수와 각자의 사망 원인이 표시된 팀 사망 화면으로 이동한다. 사망 UI는 1인 모드와 같은 고운바탕·중앙 패널·반투명 어두운 배경·청록 주 버튼·차분한 보조 버튼으로 통일한다. 메인 썸네일 디자인은 사망 화면에 사용하지 않는다.
- 각 사망 시점에서 마지막 10회 행동 해소(플레이어 이동 또는 적 이동)와 그 직전 장면을 최대 11개 보관한다. 이전/이후 버튼으로 자유롭게 살펴보며 플레이어 실선·적 점선·사망 위치 ×를 표시한다. 10회의 전체 팀 라운드나 본인 이동 10회만을 뜻하지 않는다. 첫 사망자의 기록은 동료가 계속 플레이해도 변하지 않는다. 1인 모드의 5수 기록은 변경하지 않는다.
- 복기는 별도 지연 로딩된 렌더러에서 실행한다. 방장의 실제 전투 상태를 과거 상태로 덮어쓰지 않으며 생존자의 게임/선택 시간을 멈추지 않는다. 복기 데이터는 사망 시 별도 메시지로 한 번 보내고, 최종 결과에도 포함한다. 정상 매 프레임/행동 메시지마다 반복 전송하지 않는다.
- 위험한 계약은 첫 생존 플레이어가 선택하며 팀 전체에 적용한다.
- 보스 예고 공격은 두 플레이어 모두에 판정한다. 안전 칸은 두 플레이어의 후보를 합쳐 공유한다.

## 로컬 테스트

`http://localhost:8000/coop.html`에서 DEV를 누른다. 실제 Supabase 접속 없이 두 시점을 실행한다. 양쪽 AUTO, 개별 AUTO, 일시정지, 다음 단계, ×1~4, 기물 변경, XP, 특성 획득/강화, 보스 소환, 적 소환/삭제를 제공한다.

일반 방에서는 시점을 하나만 렌더링한다. DEV의 분할 화면은 두 시점을 비교하기 위한 테스트 화면이다. 스냅샷은 상태 변경 시 생성하며 매 프레임 복제하지 않는다.

## 검증

```sh
npm run test:coop-session
npm run test:coop-ui
npm run test:traits
npm run test:enemies
npm run prepare:web
```

`scripts/test-coop-session.cjs`는 실제 게임 VM에서 원래 AI의 목적지, 내구도 타격, 처치, 팀 공유 XP/특성과 2인 특성 6종, 승급·목걸이 추가 행동, 12웨이브 지형, 보스, 최근접 플레이어 포획을 확인한다. 순서 제어는 별도 가짜 시계로 P1/P2, 보상 선택 대기, 재선택, 오래된 라운드 거절, 배속·정지를 검증한다.

`scripts/test-coop-dev-browser.mjs`는 별도 CDP Chrome(9225)과 로컬 서버(8000)에서 실제 포인터로 320×568, 390×844, 844×390, 768×1024, 1440×900 화면을 검증한다. 버튼 중앙 클릭, 넘침, 진행 막대·정지, DEV 도구, 실제 게임 진행과 두 시점의 플레이어 상태 일치를 확인한다. 캡처와 측정 JSON은 `/tmp/coop-dev-*`에 저장한다. 이는 기계적 레이아웃/조작 검사이며 실제 사용자 사용성 평가가 아니다.

`scripts/test-coop-network-browser.mjs`는 서로 다른 브라우저 창 두 개에서 방 생성/참가, 각자 시점, AUTO 입력, 위치·웨이브 동기화, 방장 퇴장을 확인한다. Supabase SDK 대신 로컬 BroadcastChannel 어댑터를 사용하므로 **실제 Supabase 연결·모바일 크로스플레이·지연/패킷 손실·장시간 안정성은 미검증**이다.

v0.16.1의 카메라 정책은 `test-coop-session.cjs`에서 연속 선택 중 동료 유지, 수동 시점 유지, 자기 선택 기회 복귀, 사망한 동료 제외를 검증했다. 브라우저 5개 크기에서도 실제 카메라 버튼을 눌러 시점 전환과 다른 플레이어 카메라의 독립성을 확인했다. 이 검증은 전투·밸런스 변경을 포함하지 않는다.

v0.16.2는 `scripts/test-coop-death-browser.mjs`에서 390×844/1440×900 실제 렌더러에 동일한 적 배치 테스트 상태를 주입해 사망 전개를 검증했다. 실제 포인터로 개인 사망 안내, 이전/이후 복기, 관전 중 복기 재진입, 팀 사망 결과와 두 플레이어별 복기를 확인했다. 복기가 열린 동안 별도 단계 입력으로 생존자의 실제 게임이 진행됨을 확인했다(이 단계 입력은 프로그램 방식). `/tmp/coop-death-{width}.png`, `/tmp/coop-replay-{width}.png`에 캡처를 남긴다. 네트워크 브라우저 테스트는 주입한 사망 상태를 사용해 게스트에게 두 복기 기록이 전달되고 재생되는 것까지 확인한다. 실제 Supabase 연결 검증은 아니다.

## 남은 제한

- 방장이 권위 상태를 계산하며 Supabase는 중계한다. 방장이 나가거나 앱이 백그라운드에서 멈추면 진행이 중단될 수 있다. 호스트 이전/재접속은 없다.
- 스냅샷 전체를 보내는 알파 구조다. 메시지 크기·무료 할당량을 실제 서비스에서 측정하지 않았다. 무료 무제한 운영을 보장하지 않는다.
- v0.16.4에서 적 이동 순서를 1인과 같은 가까운 순으로 맞췄다. 2인 전용 스폰 배율(`BALANCE.spawnScale`)은 시뮬레이션에서 효과가 구분되지 않아 1로 둔다(`docs/balance/coop-v0164-report.md`). 성장·시너지 전용 조정은 하지 않았다. 자동 AI도 협력 전용 탐색이 아니다.
- 코옵 랭킹은 아직 연결하지 않았다. 별도 팀 점수 규칙·서버 검증·2인 기록 등록 중복 방지 설계가 필요한 후속 과제로 남긴다. 1인 랭킹은 기존 기능을 유지한다.
- 실제 iPhone/Android 기기 성능과 오디오 자동 재생 정책은 별도 검증이 필요하다.

커밋·푸시·배포는 수행하지 않았다.
