# Co-op UI verification — v0.15.3

2026-10-21. 기존 싱글플레이 키 아트와 로컬 Bungee/Gowun Batang 폰트를 재사용했다. 새 이미지나 폰트 의존성은 추가하지 않았다. 방 연결·턴 판정 규칙은 변경하지 않았고, 화면 전환 시 배경을 선택할 상태 속성만 추가했다.

## 검사 조건과 결과

- 로컬 합성 픽스처 + 별도 Chrome headless, CSS px 기준.
- 실제/요청 뷰포트: 320×568, 390×844, 844×390, 768×1024, 1440×900.
- 로비·대기·플레이·종료 각 4상태, 총 20개 화면에서 가로 넘침/텍스트 가로 잘림/브라우저 예외 0건.
- 각 뷰포트에서 두 폰트의 로드와 적용된 폰트 패밀리, 로비/종료 배경 이미지, 플레이 보드 높이와 화면 경계를 확인했다.
- 짧은 화면의 로비는 내부 스크롤을 허용한다. 하단 컨트롤이 항상 첫 화면에 들어온다는 주장은 하지 않는다.
- 390px 모바일 및 PC 스크린샷을 검토했다. UI가 게임 캔버스를 가리지 않도록 로비 이미지 배경과 보드 배경을 분리했다.
- 실제 포인터 입력으로 잘못된 참가 코드 안내, 종료 화면에서 로비로 복귀, 방 나가기 3/3 동작을 확인했다.
- `npm run test:coop-ui`: 공유 이미지/폰트 파일, 기존 컨트롤 ID, 입력 라벨, 픽스처 코드 미포함 검사.
- 기존 적/플레이어 특성 테스트, 웹 빌드, JS 문법 및 diff 공백 검사 통과.

## 범위와 한계

검사 중 외부 통신을 비활성화하고 대기/플레이 상태를 주입했다. 실제 두 기기 간 Supabase 연결 성공 여부를 확인한 테스트는 아니다. 실제 iPhone의 렌더 성능, 손가락 조작감, 보조공학 사용성, 모든 배경 위치에서의 명암비는 별도 검증이 필요하다. 이 결과를 미적 품질 점수나 접근성 인증으로 해석하지 않는다.

로컬 QA 원본은 `/tmp/its-turn-coop-ui-results.json`, `/tmp/its-turn-coop-{390,1440}-{lobby,waiting,playing,end}.png`에 보관했다. 픽스처 서버와 브라우저는 검사를 마친 뒤 종료했다.

## v0.15.4 — 간결한 로비와 팝업

로비 설명·한글 부제·상시 초대 코드 입력을 제거하고 CREATE ROOM / JOIN ROOM / HOW TO PLAY 세 버튼으로 정리했다. 초대 코드는 JOIN ROOM의 네이티브 dialog/form에서, 간단 설명은 HOW TO PLAY dialog에서 확인한다. 로비의 상태 영역은 기본적으로 비어 있고 오류·동작 결과만 표시한다.

동일한 5개 뷰포트에서 로비·참가 팝업·설명 팝업·대기·플레이·종료 총 30개 상태를 검사했다. 폰트 로드, 가로 넘침 및 브라우저 예외 검사를 통과하고 모바일 스크린샷을 검토했다. 추가 실제 포인터/키보드 테스트에서 다음을 확인했다.

- JOIN ROOM은 팝업만 열며 접속을 시작하지 않음. 입력창으로 초점 이동.
- 빈 코드 Enter 제출은 팝업 내 오류 안내만 표시하며 접속하지 않음.
- 유효한 소문자 코드의 Enter 제출은 대문자로 정규화해 정확히 한 번 모의 참가 호출. 접속 상태 전환 시 팝업 닫힘.
- Esc 및 닫기 버튼으로 닫기, 설명 팝업의 Tab 초점 범위 유지, 바깥 클릭으로 닫기와 열었던 버튼으로 초점 복귀.

실제 외부 네트워크 대신 로컬 모의 Supabase 채널을 사용했다. 해당 입력 테스트는 실제 두 기기의 접속 성공을 입증하지 않는다. 팝업을 포함한 원본 캡처는 `/tmp/its-turn-coop-390-{lobby,join,help}.png`, 입력 검사 스크립트는 `/tmp/its-turn-coop-dialog-check.mjs`에 보관했다. 실제 모바일 소프트 키보드와 스크린리더는 미검증이다.

## v0.15.6 — 한 화면 로컬 DEV

사용자의 변경 요청에 따라 코옵 로비 좌하단에 체크박스가 아닌 DEV 버튼을 추가했다. 클릭하면 로컬 두 플레이어와 적을 생성하고 두 플레이어 AUTO를 켠 상태로 바로 시작한다. 실제 Supabase 채널 및 연결 라이브러리 초기화 없이 같은 이동·턴 판정 함수를 사용한다. 연결 라이브러리는 실제 방 생성/참가 시에만 초기화하며, CDN 로딩은 로컬 DEV 실행을 막지 않는다. 이 모드는 네트워크 동기화 검사를 대체하지 않는다.

하단 개발 도구: 양쪽 AUTO 동시 제어, 각 플레이어 AUTO, 일시정지/재개, 한 턴 진행, ×1/×2/×4 속도, P1/P2 조작 전환, 현재 코옵 지원 기물(나이트/비숍) 전환, 적 내구도 선택, 폰/룩 소환, 적 삭제, 재시작, 도구 숨기기/보기. 종료 화면에서도 로컬 재시작이 가능하다. 정지 상태에서 시간 제한 없이 수를 고르고 수동으로 턴 판정할 수 있다. 퇴장 시 타이머와 로컬 모드를 초기화한다.

## v0.15.7 — 4단계 배속과 남은 시간 바

2026-10-21. DEV SPEED를 ×1 → ×2 → ×3 → ×4 → ×1 순환으로 변경했다. 선택 시간 1800ms와 판정 여유 20ms, 턴 사이 420ms 지연이 모두 배속으로 나누어진다. 진행 중 배속 변경 시 남은 선택 시간 비율을 보존하며, 판정 후 대기 중 변경도 적용한다. 숫자로 표시하던 초 단위를 제거하고 네이티브 progress(0–100)로 남은 선택 시간을 표시한다. 정지 시 바도 멈추고, 선택 외 상태는 비운다.
